## 1A. 비치헤드 구매자 (지금 판다) — AI-native 스케일업 CTO / 공동창업자

**왜 이 사람이 지금 구매자인가:** 자기 실행 경로를 소유해 우리 제품(실행 전 통제 + 시맨틱 kill-switch)이 끝까지 붙고, 기존 아웃리치 파이프라인으로 도달 가능하며, 모의 인터뷰·데모·유일 실신호(라이너)가 전부 이 페르소나를 가리킨다.

### 프로필

| 항목 | 내용 (가설) |
|---|---|
| 역할 | CTO / 공동창업자 / VP Eng. AI-native B2B SaaS 스케일업(50~300명, Series A~C)에서 제품 에이전트 아키텍처와 AI 인프라 예산을 소유 |
| 산업 | 제품 코어가 LLM 에이전트인 회사 — AI 검색·리서치, 버티컬 에이전트(법률·의료·커머스), AI CS |
| 배경 | 엔지니어링 리더, AI/인프라 깊음. **만들 능력은 있으나** 제품 로드맵과 리소스가 경쟁 |
| 예산 권한 | AI 인프라 지출($50K~$500K/월) 직접 소유. 투자자에게 gross margin 방어 압박 |
| 보고 관계 | CEO/이사회에 gross margin·유닛 이코노믹스 보고, **투자 실사** 대응 |

### 목표 (성공 기준)

- LLM 비용을 **COGS의 20% 밑**으로 유지(지속가능 AI SaaS 기준선)
- **고객 1명당·기능별 유닛 이코노믹스**를 실시간으로 설명
- 폭주 루프를 **예산 태우기 전에 차단**
- 투자 실사에서 유닛 이코노믹스를 숫자로 방어

### Pain Points

1. **비-LLM이 유발 에이전트에 안 붙는다.** 멀티스텝 툴 콜 + 외부 검색/크롤링 API가 인보이스의 ~41%인데(데모 tab1), 흩어져서 고객·기능 단위로 귀속 안 됨.
2. **추정은 되나 감사등급 귀속 불가.** "고객 A의 원가"를 서버 용량 기준으로 어림은 하나, 이사회·실사에 낼 수준(감사등급)으론 별도 데이터 구조화 + 상시 파이프라인 필요(라이너 2차 직접 발화).
3. **폭주 루프가 조용히 예산을 태운다.** $47K/11일류 무한 재시도 사고 — 실행 전 차단(하드리밋)이 없음.
4. **자체 거버넌스 구축이 제품 로드맵과 경쟁.** 만들 순 있지만 그 시간에 제품 기능을 만들어야 함 = buy-vs-build ROI.
5. **gross margin 압박.** 투자자가 LLM 비용/COGS 비율을 실사에서 본다.

### 구매 트리거 (가설 — 인터뷰로 검증)

| 트리거 | 상황 |
|---|---|
| **펀드레이징 / 투자 실사** | 유닛 이코노믹스·gross margin을 숫자로 요구받을 때 |
| **gross margin 경고** | LLM 비용이 COGS 20%를 넘어 마진이 흔들릴 때 |
| **폭주 루프 사고** | 무한 루프·재시도로 예상 밖 대형 청구 발생 |
| **크레딧 소진** | 하이퍼스케일러 크레딧이 소진돼 실비 청구가 시작되는 시점 |
| **이사회 고객단위 마진 요청** | "어느 고객/기능이 마진을 먹나"를 숫자로 답해야 할 때 |

### 구매 장벽 (예상 반론)

| 반론 | 대응 방향 |
|---|---|
| **"우리가 직접 만들면 되잖아요"** (비치헤드 핵심 반론) | 만들 순 있으나 (a) 더 급한 제품을 만들어야 함(buy-vs-build ROI) (b) 크로스벤더 감사등급 + 동종 벤치마크 데이터는 **복제 불가** (c) 시장이 비 AI-native로 확장되며 이 반론은 구조적으로 죽음 |
| "LiteLLM/Langfuse로 예산 상한 걸면?" | LLM만 커버 — **비-LLM 툴/외부 API는 미귀속**. 감사등급 귀속·동종 벤치마크는 OSS가 안 줌 |
| "critical path에 프록시를 넣으라고요?" | 신뢰 사다리 1단 = **경로 밖 리포트(프록시 없음)**로 시작, 경로 소유는 신뢰 확보 후 |

### 메시지 앵글

"당신 에이전트의 진짜 유닛 이코노믹스" + "실행 전 차단" + "실사에 낼 감사등급 원가". 기술 구매자이므로 **엔지니어링 언어 사용 가능**.

### 인터뷰 검증 포인트

1. 외부 API/툴 비중이 얼마인가? 유발 에이전트에 귀속되나? (가설 0)
2. 고객 1명당 원가를 실제로 뽑아본 적 있나? 이사회/실사에 냈나?
3. 폭주 루프/예산 초과 사고 경험이 있나?
4. 자체구축 vs 구매 — 어느 지출·공수 규모에서 갈리나?
5. gross margin / LLM-COGS 비율을 추적하나? 누가 요구하나?

## 1B. 확장 구매자 — 비 AI-native 중견기업 IT Director / CTO

> 확장 물결(1B)의 경제적 구매자. 비치헤드 확보 후 진입. ⚠️ 제품 정합성 유보(벤더 SaaS만 쓰면 실행 전 통제층 미적용, 애그리게이션까지만) = `../ICP/ICP.md` §1B.

### 프로필

| 항목 | 내용 (가설) |
|---|---|
| 역할 | IT Director, CTO, 또는 VP of Operations/Digital Transformation. 200~2,000명 비 AI-native 중견기업에서 IT·디지털 전환 예산을 쥔다 |
| 산업 | 운송·물류, 제조, 금융서비스, 리테일 등 전통 산업. AI 자체가 본업이 아님 |
| 배경 | IT 운영·ERP·인프라 경력 위주. AI 엔지니어링 전문성은 낮으나 AI 벤더 계약·도입 의사결정은 이 사람이 한다 |
| 예산 권한 | IT/디지털 전환 예산 결정권자. AI 지출이 개별 벤더 계약으로 분산돼 총합을 한눈에 못 본다 |
| 보고 관계 | CFO/CEO에게 AI 투자 ROI·COGS를 설명해야 하는 위치. 이사회 보고가 요구되기 시작한 단계 |

### 목표 (성공 기준)

- AI 관련 지출 전체를 한 화면에서 파악하고 예산 초과 없이 통제
- CFO·이사회에 "AI에 이만큼 쓰고, 이 기능/프로젝트에서 이만큼 나왔다"를 숫자로 설명
- AI 투자 예산 요청 시 과거 데이터 기반 근거 있는 계획
- 규제·감사(ESG, DOT, 금융 감독 등) 대응 AI 사용 이력·비용 귀속 기록

### Pain Points

1. **청구서가 5곳에서 따로 온다.** TMS의 AI 라우팅·CS 챗봇·문서 자동화 API·수요 예측·ERP AI 모듈 — 각각 다른 벤더·주기·단위. 합산이 수동, 월말 2~3일 소모.
2. **CFO 질문에 답을 못 한다.** "올해 AI에 얼마? 어느 프로젝트가 ROI?"에 대략적 총액만, 기능·팀 단위 분해 불가.
3. **예산 초과를 사후에 안다.** 사용량 기반 AI 비용이 승인 예산을 넘어도 실시간 경보 없음.
4. **감사·컴플라이언스 리스크.** 물류 DOT / 금융 AI 거버넌스 / ESG — "어떤 AI가 어떤 업무에 얼마"를 증명 요구 증가.
5. **차지백 불가.** 부서·프로젝트·고객 단위 내부 청구를 원하나 벤더별 데이터 구조가 달라 불가.

### 구매 트리거 (가설)

| 트리거 | 상황 |
|---|---|
| **연간 AI 예산 수립 시즌** | 내년 계획을 짜야 하는데 올해 실제 사용 데이터가 없음 |
| **CFO/이사회 AI ROI 보고 요청** | 숫자로 답해야 할 때 |
| **AI 예산 초과 사고** | 월말 청구서에 예상 밖 대형 청구 |
| **규제 감사 / ESG 보고** | AI 사용 이력·비용 귀속 기록 제출 요구 |
| **신규 AI 벤더 추가** | 이미 4~5개 관리 중 하나 더 → 통합 임계점 |

### 구매 장벽 (예상 반론)

| 반론 | 대응 방향 |
|---|---|
| "각 벤더 대시보드 보면 되죠?" | 5개를 따로 보면 합산·비교·귀속 불가, 월말 수동 2~3일 |
| "IT팀 스프레드시트로 하면?" | AI 단가·청구 단위가 계속 바뀌면 스프레드시트도 계속 깨짐(P2 사례) |
| "우리 ERP에서 통합하면?" | ERP는 사후 집계만, 실시간 사용량·실행 전 통제 불가 |
| "구매 프로세스가 오래 걸립니다" | 초기 = 리포팅 전용(경로 밖) 티어로 조달 없이 진입 설계 |

### 메시지 앵글

"AI 청구서 통합 관리" + "CFO에게 AI ROI를 숫자로" + "감사 대응 비용 귀속 기록". 절감이 아니라 **가시성·통제·설명 가능성**. (엔지니어링 언어 ❌ → 운영·재무 언어.)
