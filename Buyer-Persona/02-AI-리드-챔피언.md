> ⚠️ 상태: 검증되지 않은 가설. **2026-08-03 A 주도 블렌드(CEO 결정)** 반영 — 지금 파는 **비치헤드 챔피언 = AI-native 스케일업의 AI/ML 엔지니어링 리드(§2A)**, 확장 챔피언 = 비 AI-native 중견기업 AI-ops 리드(§2B).
> 이력: 8/3 2차 재설정 때 이 파일을 비 AI-native AI-ops 리드로 전면 재작성했으나(그 내용 = §2B로 보존), 블렌드 결정으로 **비치헤드 엔지니어링 리드 챔피언(§2A)을 복원**. 이 페르소나의 실존 표본 = **라이너 Lead ML Eng**(1·2차 인터뷰).

## 2A. 비치헤드 챔피언 (지금 진입) — AI-native 스케일업의 AI/ML 엔지니어링 리드

### 프로필

| 항목 | 내용 (가설) |
|---|---|
| 역할 | Lead ML Engineer, AI/인프라 리드, 플랫폼 엔지니어. AI-native 스케일업에서 **에이전트 파이프라인·LLM 비용을 실무로 관리** |
| 산업 | AI-native B2B SaaS(AI 검색·리서치·버티컬 에이전트). 라이너 Lead ML Eng이 이 페르소나 |
| 배경 | ML/인프라 엔지니어. 비용 추적 스크립트를 직접 짤 수 있으나 **본업(제품)이 아니라 넘기고 싶어함** |
| 권한 | 툴 도입 평가·PoC 재량. 유료 계약은 CTO(경제적 구매자, §1A) 승인 필요 |
| 일상 | 비용 급증 시 각 대시보드·로그를 뒤져 원인 추적, 서버 용량 기준으로 원가 어림, 단가 개편 때 스크립트 수정 |

### 목표 (성공 기준)

- 비용 추적/귀속을 **직접 짜는 대신 넘기는 것**(본업 = 제품)
- 폭주·무의미 반복을 **자동 감지**
- CTO가 요구하는 고객·기능별 유닛 이코노믹스를 **감사등급으로** 제공

### Pain Points

1. **다중 호출 귀속이 "추정 가능 ≠ 감사등급".** 서버 용량 기준으로 어림은 되나(라이너 1차), 기능·팀·고객별 분해는 **별도 데이터 구조화 + 상시 파이프라인 비용** 필요(라이너 2차 직접 발화).
2. **유지보수가 본업을 갉아먹는다.** 자체 비용 추적 유지에 월 15~20h + 단가 개편 때 이틀 소모(P5 헬프나우 신호). "이거 그만하고 싶다."
3. **비-LLM 외부 API가 안 붙는다.** 검색·크롤링·리랭킹 API는 요청당 과금(토큰 아님) → 유발 에이전트에 귀속 안 됨.
4. **폭주 감지가 사후.** 무의미 반복 루프를 실시간으로 못 잡고 청구서 보고 안다.

### 도입 트리거 (가설)

| 트리거 | 상황 |
|---|---|
| **크레딧 소진** | 하이퍼스케일러 크레딧이 소진돼 실비 청구가 시작될 때 |
| **유지보수 부담 임계** | 비용 추적 스크립트 유지가 제품 시간을 계속 먹을 때 |
| **CTO 유닛 이코노믹스 요청** | 실사·이사회용 고객단위 원가를 감사등급으로 요구받을 때 |
| **폭주 사고** | 무한 루프로 예상 밖 청구 발생 후 |

### 도입 장벽 (예상 반론)

| 반론 | 대응 방향 |
|---|---|
| "우리가 스크립트로 짜면 되잖아요" | 짤 순 있으나 유지보수가 본업(제품)을 갉아먹음 + 크로스벤더 감사등급·벤치마크는 자체로 못 만듦 |
| "critical path에 프록시는 SLA 리스크" | 신뢰 사다리 1단 = **경로 밖 관제·리포팅**(프록시 없음)부터, 경로 진입은 신뢰 확보 후 (P5가 "관제·리포팅만 떼서 주면 볼 수도" 발화) |
| "Langfuse/CloudWatch가 토큰은 보여줘요" | 토큰 표시는 커모디티 — 우리 히어로는 **비-LLM 포함 감사등급 귀속 + 실행 전 차단** |

### 메시지 앵글

"비용 추적을 넘기고 제품에 집중" + "비-LLM까지 유발 에이전트에 귀속" + "폭주 실행 전 차단". 엔지니어 언어 OK.

## 2B. 확장 챔피언 — 비 AI-native 중견기업 AI Operations 리드

> 확장 물결(1B)의 챔피언. 코드는 안 짜고 AI SaaS 도구를 도입·운영·관리하는 실무자.

### 프로필

| 항목 | 내용 (가설) |
|---|---|
| 역할 | AI Operations Manager, 디지털 전환 담당자, "AI 도구 담당자". AI 벤더 계정·청구서를 실무로 관리 |
| 산업 | 운송·물류, 제조, 금융서비스, 리테일 등 비 AI-native 중견기업 |
| 배경 | IT 운영·데이터·비즈니스 분석 경력. **"코드는 안 짜지만 5개 AI 대시보드에는 매일 들어간다"** |
| 권한 | 소규모 도입은 재량, 큰 계약·벤더 추가는 IT Director/CTO(§1B) 승인 |
| 일상 | 월말 각 벤더 대시보드를 돌며 사용량·비용을 스프레드시트에 모아 IT Director에 보고 |

### 목표 (성공 기준)

- 월말 AI 비용 집계 시간 감소(현재 2~3일 → 수분)
- IT Director가 "AI 비용 얼마?" 물을 때 즉시 답
- 벤더가 늘어도 관리 복잡도가 비례 증가하지 않음
- 새 AI 도구 도입 전 예상 비용 파악

### Pain Points

1. **월말 수동 집계 지옥.** 벤더마다 다른 대시보드·날짜 기준·단위(토큰/API콜/좌석/요청). 합산에 2~3일, 벤더 추가 시 더 복잡.
2. **청구 단위가 달라 비교 불가.** LLM=토큰, CS AI=대화, 문서=페이지, 예측=월정액 → "프로젝트당 얼마"로 변환하는 수식이 깨지기 쉬움.
3. **어디서 튀었는지 모른다.** 30% 증가 원인을 찾으려면 각 대시보드를 하나씩.
4. **새 도구 비용 예측 불가.** 벤더 영업 추정에 의존, 실제와 다름.
5. **부서별 분리 불가.** "물류팀 vs CS팀 AI 비용" 요청에 추정치로 답.

### 도입 트리거 (가설)

| 트리거 | 상황 |
|---|---|
| **월말 집계 스트레스** | 또 2~3일 썼을 때 "자동화 없나" 검색 |
| **IT Director 보고 요청** | "AI 예산 현황 한 페이지로" |
| **벤더 추가 시점** | 4개 관리 중 하나 더 결정될 때 |
| **AI 비용 이상 탐지** | 원인 파악에 반나절+ 소모될 때 |

### 도입 장벽 (예상 반론)

| 반론 | 대응 방향 |
|---|---|
| "스프레드시트로 지금도 해요" | 단가 변경·신규 벤더 시 깨짐 = 유지보수 비용 지속 |
| "API 연동이 복잡할 것 같아요" | 신뢰 사다리 1단: 청구서 CSV/PDF 업로드만으로 시작, 연동 없이 리포팅부터 |
| "IT Director 승인 모르겠어요" | 먼저 써보고 집계 시간 감소를 수치화 → 설득 자료 생성 |

### 메시지 앵글

"AI 벤더 5개 대시보드를 하나로" + "월말 집계 2~3일 → 자동화" + "IT Director에게 즉시 보고". 엔지니어링 언어 ❌ → **운영 효율·보고 자동화** 언어.

## 두 변형의 관계 + 영업 가설

- **지금(비치헤드):** AI/ML 엔지니어링 리드(2A)가 off-path 리포트로 진입 → CTO(§1A)에게 유료 제안. 언어 = 엔지니어링·유닛 이코노믹스.
- **확장:** AI-ops 리드(2B)가 무료 티어로 집계 시간 감소 체감 → IT Director(§1B) 설득. 언어 = 운영 효율.
- **메시지 분리:** 2A = "비용 추적을 넘기고 제품에 집중" / 2B = "내 월말 집계 2~3일이 준다" / 경제적 구매자 = "이사회·실사/CFO에 숫자로 설명".
- **인터뷰 확인:** 확장(2B) 역할이 비 AI-native 중견기업에 실제 존재하는가, 아니면 IT Director 겸직인가? (겸직 시 통합 검토.)
