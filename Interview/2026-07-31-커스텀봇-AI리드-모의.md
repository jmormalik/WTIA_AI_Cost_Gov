## 인터뷰 대화록

**I:** 안녕하세요 박지훈님, 바쁘신 중에 시간 내주셔서 감사합니다. 오늘은 AI 에이전트를 프로덕션에서 운영하는 팀들이 비용을 실제로 어떻게 관리하는지 공부하고 있어요. 제품을 팔려는 게 아니라, 실제로 어떻게 일하시는지 듣고 싶어서요.

**P:** 네, 반갑습니다. 별 거 없을 수도 있는데 뭐든 도움이 되면 좋죠.

### 스크리닝

**I:** 지금 만들고 계신 AI 기능에 대해 얘기해 주세요. 실제 고객 트래픽을 받고 있나요?

**P:** 네, 저희는 유통 업체들 — 도매상이나 물류 회사들 — 에 맞춤 AI 에이전트를 만들어 드려요. 지금 고객사가 9곳이고 다 라이브예요. 재고 조회나 발주 처리, 배송 추적 같은 걸 에이전트가 처리하게 해드리는 서비스거든요.

**I:** 응답을 만들 때 모델이 검색이나 DB 조회, 외부 API 같은 툴을 스스로 호출하나요? 요청 하나에 보통 몇 번쯤 되나요?

**P:** 호출하죠. 주문 상태 조회나 재고 확인할 때는 고객사 ERP 시스템 API 붙고요, 배송 추적은 택배사 API 부르고요. 크롤링도 종종 해요. 요청 하나에 보통 서너 번? 많으면 일곱 여덟 번도 나와요.

**I:** 월 LLM/API 비용이 대략 어느 정도예요? 클라우드 크레딧으로 내고 있나요, 실비인가요?

**P:** 실비요. 대략 한 달에 한 삼사천 달러 나오는 것 같아요. LiteLLM 셀프호스팅으로 쓰고 있어서 LLM은 저희가 직접 API 쓰고 있고요.

**I:** 매출은 주로 어디서 나와요?

**P:** B2B 구독이에요. 고객사들이 월정액으로 내고요. 무료는 아예 없어요.

### 현재 워크플로

**I:** AI 비용은 지금 어떻게 확인하세요? 마지막으로 확인한 게 언제였는지, 그때 뭘 봤는지 얘기해 주세요.

**P:** 음... LiteLLM 대시보드에서 LLM 호출은 보이거든요. 그건 고객사별로 그래도 나눠 볼 수가 있어요. 제가 고객사마다 API 키 분리해서 설정해놨거든요. 그런데 그 외에 재고 조회라든지 택배사 API 같은 건... 그건 제각각이에요. 고객사 계정에서 쓰는 것도 있고, 저희 자사 계정에서 한꺼번에 쓰는 것도 있고.

**I:** 그 비용을 기능별이나 고객별로 쪼개서 볼 수 있나요? 실제로 그렇게 본 적 있어요?

**P:** LLM은 어떻게든 보이는데... 외부 API는 사실 못 봐요. 어느 고객사가 얼마나 쓴 건지 사실 잘 몰라요. (잠시 멈추며) 좀 부끄러운 얘긴데, 저희 거기까지는 제대로 정리가 안 돼 있어요.

**I:** 에이전트가 호출하는 외부 API — 재고 조회나 배송 추적 같은 것들 — 그 비용도 LLM 비용이랑 같이 보이나요, 따로 흩어져 있나요?

**P:** 따로 흩어져 있죠. LiteLLM에서는 LLM만 보이고요. 배송 API는 택배사 대시보드에 가야 보이고, ERP 연동은 또 ERP 업체 포털 들어가야 하고, 크롤링은 저희가 쓰는 서비스 거기 또 따로 보이고. 다 뿔뿔이 흩어져 있어요.

### 최근 사건 딥다이브

**I:** 최근에 AI 비용이 예상보다 튀었던 적이 있나요? 가장 최근 사례를 처음부터 얘기해 주세요 — 언제, 어떻게 알게 됐고, 그다음 뭘 하셨어요?

**P:** 크게 터진 적은 아직 없어요. 다행히... 뭐, 숫자가 워낙 작으니까 튀어도 크게 안 튀는 편인데. 음. 크롤링 비용이 갑자기 올라간 달이 있긴 했어요. 그게 고객사 중 한 곳이 상품 페이지가 많은 업체였거든요. 근데 그게 누구 때문에 얼마나 올랐는지는... 솔직히 그때도 정확히는 몰랐어요.

**I:** 그 상황에서 원인을 어떻게 찾았어요?

**P:** 찾았다기보다... 그 달에 새로 들어온 고객사가 거기밖에 없어서 '아 얘가 크롤링 많이 썼겠구나' 하고 추론한 거예요. 실제로 확인을 한 건 아니고요. (자조적으로 웃으며) 그냥 감이죠 뭐.

**I:** 그런 일이 얼마나 자주 있어요?

**P:** 자주는 아닌데, 월말에 청구서 받을 때마다 좀 불안하긴 해요. 합산 금액은 보이는데 왜 이렇게 나왔는지 설명이 잘 안 되니까요.

### 시도해본 해결책

**I:** 그 문제 때문에 뭔가 만들거나 도입한 게 있어요?

**P:** 음, LiteLLM은 그래도 도움이 됐어요. LLM 쪽은 어떻게 됐고요. 그 외에는... 사실 한번은 스프레드시트로 다 합쳐보려고 했어요.

**I:** 스프레드시트요? 그 얘기 더 해주세요. 어떻게 됐어요?

**P:** 작년이었나... 분기별로 고객사마다 원가를 정리해보고 싶었거든요. 그래서 각 대시보드에서 CSV 뽑아다가 엑셀에 붙여 넣고 합치려고 했는데. (긴 한숨) 사흘 썼어요. 근데 포기했어요.

**I:** 왜 쪼개기 어려웠어요? 뭐가 막혔어요?

**P:** 우선 청구 주기가 다 달라요. 어떤 API는 일단위로 쌓이고, 어떤 건 28일 주기로 끊기고, 어떤 건 요청 건수로 보여주고 금액으로는 안 보여주고. 그리고 단가 체계도 다 달라서요. 어떤 건 1천 건당 얼마, 어떤 건 GB당 얼마, 크롤링은 또 페이지당 얼마 이런 식이고. 이걸 고객사별로 쪼개려면 어떤 고객사가 그 기간에 얼마나 호출했는지 따로 기록이 있어야 하는데 그게 없으니까요. API들이 고객사별 사용량을 제공을 안 해줘요. 통합 합계만 줘요. (자조적으로) 결국 '에이 모르겠다' 하고 포기했어요.

**I:** 그때 사흘을 썼는데 포기하신 거잖아요. 그게 아깝다고 느끼셨어요?

**P:** 당연히 아깝죠. 근데 계속 잡고 있을 수도 없고. 저 혼자도 아니고 다른 일도 있으니까요. 그냥 덮어놓은 거죠.

**I:** 지금도 그건 해결이 안 된 상태인가요?

**P:** 네, 여전히요. 그냥 안 보는 거예요.

**I:** 비용이 나가기 전에 막으려고 해본 건 있어요? 예산 한도나 호출 제한 같은 거요.

**P:** LiteLLM에서 고객사별로 토큰 한도 걸어놓긴 했어요. 근데 외부 API는 뭐 따로 제한 걸어놓은 건 없어요. 그쪽은 어떻게 해야 할지도 모르겠고요.

**I:** 이 문제와 관련해서 돈을 내고 있는 건 있어요?

**P:** LiteLLM은 오픈소스 셀프호스팅이라 따로 내는 건 없어요. 외부 API 비용 정리 같은 걸 도와주는 도구는 따로 쓰고 있지는 않고요.

## 이중 기록 (가설 0 결측 + 가설 2 지지)

### 가설 0 결측 기록

Q-H0 ("토큰 vs 외부 API 몇 대 몇이에요?")에 대해 박지훈은 **"정확히 몰라요, 못 쪼개요"** 라고 답변.

- **결측 이유**: 외부 API(재고 조회·배송 추적·크롤링)가 고객사 계정·자사 계정에 흩어져 있어 합산 자체가 불가.
- **판정 처리**: 가설 0 생존 카운트에서 **결측(비율 미확보)으로 분류** — 분리 불가 응답을 "0%"나 "부정"으로 오산정하지 않는다.
- **감(gut) 언급**: 본인은 "LLM이 절반보다 많겠지, 외부 API가 30~40% 될 수도 있을 것 같다"고 언급. 단, 확인 불가로 판정식 입력 불허.

### 가설 2 지지 기록 (귀속 미성숙 증거)

동일 응답이 **가설 2 ("귀속이 안 됨 — 총액은 보이나 분해가 안 된다")의 직접 지지 증거**로 별도 기록.

- **핵심 발언 (원문)**: *"정확히 몰라요, 못 쪼개요."*
- **행동 증거 (Q-H0-b)**: 작년에 스프레드시트로 합쳐보려다 **3일 쓰고 포기** — "API마다 청구 주기도 다르고 단가 체계도 달라서요." 워크어라운드를 시도했으나 기술적 장벽으로 중단.
- **구조적 원인 (박지훈 직접 설명)**:
  1. API마다 청구 주기 상이 (일단위 / 28일 주기 / 월별)
  2. 단가 체계 상이 (건당·GB당·페이지당)
  3. 외부 API 벤더들이 **고객사별 사용량을 제공하지 않음 — 통합 합계만 제공**
- **LLM vs 외부 API 이중 구조**: LiteLLM으로 LLM 비용은 고객사별로 가시화 → 그러나 외부 API는 전혀 귀속 불가. **LLM 귀속 ≠ 전체 귀속** 임을 현업이 직접 실증.

## 시사점

### 핵심 인사이트

1. **"총액은 보이나 분해가 안 된다" = 현장 언어로 직접 확인.** 박지훈의 "월말에 청구서 받을 때마다 좀 불안한데 왜 이렇게 나왔는지 설명이 안 돼요"는 가설 2 Villain 언어가 현업에서 실제로 통용됨을 시사.

2. **LLM 귀속과 외부 API 귀속은 완전히 다른 문제.** LiteLLM 같은 LLM 게이트웨이가 해결하는 것은 LLM 비용 귀속뿐. 외부 API(재고·배송·크롤링)는 벤더 분산·청구 체계 이질성으로 별도 레이어 필요. "LiteLLM 있으니까 됐잖아요" 반론에 대한 실전 반박 근거.

3. **B2B SaaS에서 "고객사별 원가 모르고 가격 책정"은 직접적 COGS 귀속 필요성 신호.** 현재는 규모가 작아 버티고 있으나, 성장 시 자연 구매 트리거. 이 세그먼트(B2B AI 에이전트 구독)의 패턴이 반복될 경우 ICP 정합성 추가 방증.

4. **포기 사건이 "워크어라운드 시도"의 증거.** 3일 작업 후 포기 = 문제의 존재를 인식하고 자체 해결을 시도했으나 기술·구조적 장벽에 막힌 케이스. 심각도는 아직 낮으나 잠재 구매 후보군.

5. **소개 의향 있음.** HR 및 제조업 분야 유사 B2B AI 에이전트 운영자 2명 연결 가능성 — 파이프라인 확장 기회.

### 이 인터뷰의 한계

- 가설 0 비율 미확보: 외부 API 비중이 "감으로" 30~40% 언급됐으나 검증 불가. 판정식 입력 불허.
- 심각도 신호 2/3으로 착수 게이트 미충족. 고객사 증가 시 재방문 가치 있음.
- Q-P2~P5 가격 신호 대부분 미확보 — 35분 내 커버 한계. 2차 인터뷰 또는 소개 연결 후 보완 권장.
