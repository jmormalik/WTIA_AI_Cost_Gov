## 인터뷰 대화록

**I:** 안녕하세요 정태호 님. 시간 내주셔서 감사합니다. 저는 AI 에이전트를 프로덕션에서 운영하는 팀들이 비용을 어떻게 관리하는지 공부하고 있어요. 제품을 팔려는 게 아니라, 실제로 어떻게 일하시는지 듣고 싶어서요. 괜찮으시면 지금 돌리고 계신 AI 기능에 대해 얘기해 주실 수 있을까요?

**J:** 네, 뭐 말씀하세요. 저는 헬프나우에서 인프라 맡고 있는데요, CS 자동화 에이전트 운영하고 있고요. 실제 고객사 120곳한테 프로덕션 트래픽 서빙 중이에요.

**I:** 에이전트가 응답을 만들 때 외부 API나 검색, DB 조회 같은 툴을 스스로 호출하나요? 대략 요청 하나에 몇 번쯤 되는지 감이 있으세요?

**J:** 당연히 호출하죠. 주문 조회, 배송 추적, 고객사 CRM 연동… 요청 하나에 평균 대여섯 번은 나가요. 단순한 질문도 컨텍스트 끌어오려면 서너 개는 기본이고요.

**I:** 월 LLM/API 비용이 대략 어느 정도예요? 크레딧으로 내고 있나요, 실비인가요?

**J:** 실비예요. 지금 월에 $45K 수준이에요. 크레딧은 초반에 좀 썼고, 지금은 전부 카드 청구되고 있어요.

**I:** 매출은 주로 B2B 계약인가요, 구독인가요?

**J:** B2B 구독이에요. 고객사가 120곳이고요, 계약 기반 월 구독이에요.

**I:** 감사합니다. 그럼 AI 비용은 지금 어떻게 확인하세요? 마지막으로 확인하신 게 언제였고, 그때 뭘 보셨는지 얘기해 주시겠어요?

**J:** 저희는 자체 대시보드 있어요. 매일 오전에 자동으로 슬랙으로 리포트 날아오고요.

**I:** 오, 자체 대시보드를요. 그 비용을 기능별이나 고객사별로 쪼개서 볼 수 있나요?

**J:** 네. 고객사별로 보여요. 기능 단위도 어느 정도는요.

**I:** 에이전트가 호출하는 외부 API — 주문 조회나 외부 연동 같은 것들 — 그 비용도 LLM 비용이랑 같이 보이나요?

**J:** 저희는 이미 다 만들었어요. LLM이든, 외부 API든, 툴 콜이든 다 하나로 보여요. 2년 전에 비용 폭주 사고 났고, 그때부터 전부 자체 구축했거든요.

**I:** 어떻게 만드셨어요?

**J:** (잠깐 뜸) 뭐 별거 있나요. CloudWatch 로그 긁어서 파이프라인 짜고, 외부 API는 각 서비스 청구 API 붙여서 집계하고, 그걸 S3에 쌓아서 대시보드 연결한 거죠. 처음엔 엔지니어 두 명이 한 달 반 정도 붙었어요.

**I:** 그게 지금도 잘 돌아가고 있어요?

**J:** 돌아가죠. 근데 관리가 좀… (뜸) 뭐, 어떻게든 굴러가고 있어요.

**I:** 유지보수에 한 달에 시간이 얼마나 들어가요? 프로바이더가 단가 바꾸거나 모델 개편 있을 때는요?

**J:** (조금 쓴웃음) 월 15~20시간은 들어가요, 담당 엔지니어 혼자요. 근데 단가 개편이 문제예요. 예를 들어 Anthropic이 모델 버전 바꾸거나 요금 체계 개편하면, 그때마다 이틀은 통째로 날려요. 파이프라인 로직이 전부 가격 구조에 박혀 있어서요. 담당 엔지니어가 얼마 전에 저한테 따로 와서 "이거 그만하고 싶다"고 했어요.

**I:** 그 엔지니어 시간을 다른 데 쓸 수 있다면 뭘 할 것 같아요?

**J:** 당연히 고객 기능이죠. 인프라 유지보수에 시니어 한 명이 달마다 20시간씩 쓰는 게 맞냐고 하면… 솔직히 아니죠. 근데 안 할 수도 없잖아요. 고객사별 원가를 모르면 계약가 조정도 못 하고.

**I:** 2년 전 비용 폭주 사고 얘기가 나왔는데요, 그때 어떻게 됐어요?

**J:** 에이전트 하나가 외부 API 재시도 루프에 걸렸어요. 주문 조회 API가 간헐적으로 타임아웃이 났고, 에이전트가 계속 재시도를 했는데 그걸 며칠 동안 못 잡은 거예요. 청구서 나왔을 때 그달 LLM+API 비용이 평소 대비 3배가 나온 거예요. 그때부터 "이거 안 된다"고 해서 시스템 짠 거고요.

**I:** 원인을 찾는 데 시간이 얼마나 걸렸어요?

**J:** 청구서 나온 다음날부터 로그 팠는데, 확인에만 이틀 걸렸어요. 어느 에이전트인지, 어느 고객사 요청에서 시작했는지 추적하는 게 당시엔 아무것도 없었으니까요.

**I:** 지금은 그런 사고가 재발한 적 있어요?

**J:** 완전히 동일한 건 없었는데, 외부 API 단가가 슬그머니 오른 걸 한 달 뒤에 안 적은 있죠. 그 달 청구가 좀 크게 나왔는데 뒤져보니까 API 단가 변경이 있었더라고요.

---

**I:** 이 문제 때문에 도입을 검토했던 외부 도구는 없었어요?

**J:** LiteLLM은 봤죠. 근데 안 넣었어요.

**I:** 왜요?

**J:** (단호하게) **critical path에 외부 프록시 못 넣어요. 장애 나면 우리 SLA가 죽으니까요.** 고객사가 CS 봇이 안 된다고 하면 우리가 계약 위반이 되는 구조예요. 그래서 경로 안에 서드파티 레이어를 끼우는 건 원칙적으로 안 해요.

**I:** 그 원칙이 언제부터 생긴 건가요? 어떤 경험에서요?

**J:** (잠깐 생각) 명시적 원칙이라기보다, 2년 전 사고 이후 팀 안에서 암묵적으로 굳어진 거예요. 외부 의존을 줄이자는 방향으로 자연스럽게 가게 된 거고요. 실제로 LiteLLM은 **OSS니까 셀프호스트도 가능한 건 알아요. 근데 그거 운영하고 버전 관리하는 게 또 일이잖아요.** 차라리 직접 짠 게 통제 가능하다고 봤고요.

**I:** 말씀하신 숫자가 나온 김에 여쭤볼게요 — 월 $45K에서 LLM 토큰 비용과 외부 API 비용을 쪼개면 대략 몇 대 몇이에요? 감이면 됩니다. 숫자는 익명·범위로만 정리하고, 회사가 식별되게 쓰지 않아요.

**J:** (잠깐) 대략 토큰이 78, 외부 API가 22 정도? 그러니까 주문 조회, 물류사 API, 외부 고객 CRM 연동이 $10K 정도 되고, 나머지가 LLM 토큰이에요.

**I:** 그래서 뭐 파시려고요?

**I:** (흔들리지 않고) 아직 아무것도 만들지 않았어요. 솔직히 뭘 만들어야 할지도 모르는 상태예요. 이 쪽에서 어떻게 일하시는지 배우는 중이에요. 오늘처럼 실제 경험을 들어야 그 다음 판단을 할 수 있을 것 같아서요.

**J:** (약간 경계 풀리며) 뭐, 그렇다고 하시면요. 어차피 이 공간에 솔루션 갖다 팔려는 사람들 많이 봤는데 대부분 현업 복잡도를 몰라서요.

**I:** 맞아요, 그래서 여쭤보는 거예요. 외부 API가 $10K면 전체의 22%인데요, 그 비용을 지금 대시보드에서 어떻게 보여주고 있어요? 에이전트 단위로 나오나요, 고객사 단위로 나오나요?

**J:** 고객사 단위로는 나오는데, 에이전트 단위로 쪼개는 건 아직 완전하지 않아요. 한 고객사에 에이전트 여러 개가 붙어 있는 경우엔 합산만 보여요.

**I:** 그게 불편하다고 느낀 적은요?

**J:** 있죠. 계약 갱신 때 특정 고객사가 "왜 이만큼이냐"고 물으면 설명이 좀 러프해요. 어느 흐름에서 얼마 나갔는지 딱 떨어지게 못 보여주는 경우가 있어서요.

**I:** 비용 추적, 리포팅 하는 데 지금 한 달에 사람과 시간이 얼마나 들어가요? 담당 엔지니어 한 분 말씀하셨는데, 거기서 다예요?

**J:** 담당 엔지니어가 15~20시간이고요. 단가 개편 때는 이틀씩 통째로요. 그리고 월말에 고객사 리포트 정리하는 게 또 반나절 정도? PM이 엑셀로 마무리하는 게 남아 있어서요.

**I:** 비용을 추적하고 귀속하는 이 일을 이런 도구에 아웃소싱한다면 — 아직 존재하지 않는 가상이에요 — 어떤 조건이 있어야 검토해볼 수 있어요?

**J:** (잠시 생각) 우선 경로 안에 끼워 넣는 건 안 돼요, 아까 말씀드린 대로요. 근데 만약에… **관제·리포팅만 떼서 주는 거면 볼 수도 있죠.** 로그를 사이드에서 받아서 리포팅 레이어만 해주는 거라면, 경로에 뭔가 끼워 넣는 게 아니니까요. 그 부분만 해결해주면 엔지니어 시간도 절약되고.

**I:** 결제나 도입 결정은 보통 누가 해요?

**J:** 저 수준에선 CTO 결재예요. 인프라 도구는 제가 제안하고 CTO가 승인하는 구조고요. 재무는 분기 리뷰 때 보는 수준이에요.

**I:** 지금 팀을 잠 못 들게 하는 문제 세 가지를 꼽으면 뭐예요?

**J:** (손가락 꼽으며) 하나는 에이전트 정확도, 고객사마다 케이스가 달라서. 두 번째는 SLA — 업타임 못 맞추면 계약 위반이니까. 세 번째는 뭐… 비용 예측 가능성이죠. 고객사 늘어날수록 API 비용이 어떻게 튈지 계산이 안 맞는 경우가 생겨요.

**I:** 뭔가 만들게 되면 초기 버전을 보고 피드백 주실 수 있어요?

**J:** (뜸) 뭘 만드냐에 달렸죠. 관제·리포팅이라면 볼게요. 경로에 끼우는 거면 얘기가 달라요.

**I:** 감사합니다. 같은 문제를 겪고 있을 만한 분 두세 분 소개해 주실 수 있어요?

**J:** 음… 알고 지내는 데 한두 명은 있는데, 제가 직접 물어보고 연락처 드릴게요. 무작정 연결해드리기엔 좀 그래서요.

**I:** 물론이죠. 편하실 때 연락 주시면 됩니다. 오늘 정말 도움이 많이 됐어요. 감사합니다.

**J:** 네, 도움이 됐다니 다행이네요.

## 시사점

### 가설 0 (tool-call 비중 15%+) — 생존
- 토큰 78 : 외부 API 22, 외부 API 월 ~$10K
- 판정식: 22% (15%+ ✅) & 절대액 $10K ($2K+ ✅) → **생존 카운트 +1**
- 라이너(추정치 공개 거절)에 이어 두 번째 비율 데이터 포인트 확보

### 가설 3 ("직접 만들었다" 반론) — 뚫림
- 첫 반응은 "이미 다 만들었어요"였지만, "어떻게 만드셨어요?" 단 하나로 유지보수 실비용 전개
- 월 15~20시간, 단가 개편 시 이틀, 담당 엔지니어 "그만하고 싶다" = 자체 구축의 **숨겨진 실비용 3종 세트**
- 이 패턴은 실 인터뷰에서도 동일 전술 적용 가능 — "어떻게 만드셨어요?"가 핵심 열쇠

### 가설 4 (critical path / OSS 논리) — 재확인, 패턴 확립
- 라이너 ML Eng에 이어 동일 논리 반복: "critical path엔 외부 프록시 못 넣어요"
- OSS 추가 레이어: "셀프호스트 가능한 건 알지만 운영이 또 일"이라는 LiteLLM 평가 → OSS라도 운영 부담은 남음
- **이 두 가지 발언은 피치 덱 반론 섹션의 실증 인용으로 활용 가능** (익명화 후)

### 경로 밖 진입 전략 (신뢰 사다리 1단) — 직접 신호 확보
- "관제·리포팅만 떼서 주는 거면 볼 수도 있죠" = Kyber의 신뢰 사다리 1단(off-path report)을 현업이 자연스럽게 언급
- 라이너 회신의 "외부 솔루션이면 빠르다"와 동일 방향: **off-path 리포팅이 진입 전략으로 유효함을 두 번째 인터뷰에서 재확인**

### 자체 구축 반론에 대한 실전 교훈
- "이미 다 만들었어요"에 방어하거나 솔루션 냄새 풍기면 대화가 끊김
- 방어 없이 "어떻게 만드셨어요?"로 받으면 → 유지보수 실비용, 담당 엔지니어 고통, 미완성 영역(에이전트 단위 귀속)이 자연스럽게 나옴
- "그래서 뭐 파시려고요?" 공격에 아이디어 피칭 대신 "아직 배우는 중"으로 일관 → 경계가 풀리고 힌트 발언으로 이어짐

### 미확인 / 후속 과제
- 에이전트 단위 과금(Q-P1)에 대한 수용성 직접 확인 필요
- 지불 이력(심각도 신호 ③) 없음 — 인건비 환산으로 우회 정당화는 가능하나, 외부 도구 실제 결제 경험 후속에서 확인 필요
- "관제·리포팅 레이어" 구체 기능 요건 (어떤 리포트, 어느 주기, 어떤 포맷) 미확인 → 2차 미팅에서 확인 가치 높음
